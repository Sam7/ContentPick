# Current risks

- **Full P0 acceptance remains open.** M0–M3 are Windows-local verified. M3.5 must implement the approved shell and visual contract, preserve working domain behavior, verify all P0 criteria, and migrate legacy `excludeExtensions` settings transactionally before M4.
- **Legacy filter migration.** Settings v1 persists an active `excludeExtensions` policy. Convert it to equivalent visible exclude-path rules with backup/validation/atomic save; preserve the original on unrepresentable rules or failure. M3.5.4 acceptance fixtures are specified in ROADMAP and the redesign contract.
- **Scale results are host-specific.** Current debug WebView2 observation is 636.7 MiB process-tree working set across 8 processes at 20k source / 100k ignored fixture. There is no approved absolute memory threshold; samples can miss brief peaks. Treat this as a baseline, not a cross-host guarantee.
- **Earlier test-host process attribution is unresolved.** A scale-harness PID-reuse defect caused a diagnostic cleanup attempt to include unrelated Windows processes. A read-only audit found 129 of 133 logged identities still running; four were absent, with no evidence to attribute their exit. The defect is fixed with creation-time ancestry, a pinned root, and path/identity-verified process handles; the corrected scale run passed. Do not claim the four absent processes were terminated or exited naturally.
- **Platform/release evidence is Windows-only.** macOS build/runtime, remote CI, installers, signing/notarisation and public release are not verified. Keep these release gates explicit in M5.

M2 policy bounds, recursive Git ignore behavior, and M3 native scale/cancellation evidence are closed locally; see [`REVIEW_LOG.md`](REVIEW_LOG.md) and [M3 measurements/limitations](../testing/2026-10-09-native-scale.md).
